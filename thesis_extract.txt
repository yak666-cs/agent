I
摘 要
随着人口老龄化进程的加快和慢性病患病率的持续上升，出院后慢病患者的随访管
理和用药依从性问题日益凸显。传统的人工随访方式存在效率低下、覆盖不全、反馈不
及时等突出问题，难以满足日益增长的患者管理需求。针对这一问题，本文基于自动化
工作流平台 n8n，设计并实现了一套慢病患者智能随访与用药提醒系统，旨在通过信息
化手段提升慢病患者的出院后管理质量，改善用药依从性和康复效果。
系统采用前后端分离的架构设计。后端基于 n8n 工作流引擎构建，利用可视化流程
编排能力，实现了定时用药提醒、康复问卷推送、消息通知、健康资讯抓取等核心功能
的自动化运行；前端采用微信小程序框架，分别提供患者端和医院端两套独立入口。患
者端具备用药查询、康复问卷填写、医生出诊查看、智能小助手对话等功能；智能小助
手基于 n8n 的 LangChain 集成能力构建 AI 智能体，绑定 4 个自定义 Tool，使用 DeepSeek
Chat 模型（temperature 0.3）。医院端支持消息推送、出诊信息管理、患者数据管理和
康复问卷评估等功能。同时，系统集成了基于 FAISS 向量数据库和 BGE-small-zh 中文
嵌入模型的轻量级检索增强生成（RAG）知识库，为智能小助手提供可靠的医学知识检
索能力，确保回答的专业性和准确性。
系统使用 MySQL 数据库存储患者信息、用药记录、消息通知、康复问卷、医生出
诊、健康资讯等业务数据，通过 n8n 的 Webhook 接口实现前后端数据交互。测试结果
表明，系统各功能模块运行稳定，定时任务执行准确，RAG 知识库检索的响应速度和
准确度满足实际使用需求。本系统为慢病患者的出院后管理提供了一套低成本、高效率、
易扩展的自动化解决方案，具有良好的实际应用价值和推广前景。
关键词：n8n；AI 智能体；慢病管理；智能随访；RAG 知识库

II
Abstract
With the acceleration of population aging and the rising prevalence of chronic diseases,
the challenges of post-discharge follow-up management and medication adherence for chronic
disease patients have become increasingly prominent. Traditional manual follow-up methods
suffer from low efficiency, incomplete coverage, and untimely feedback. To address these
issues, this paper designs and implements an intelligent follow-up and medication reminder
system for chronic disease patients based on the n8n workflow automation platform, aiming
to improve the quality of post-discharge management, medication adherence, and
rehabilitation outcomes through informatization approaches.
The system adopts a front-end and back-end separation architecture. The backend is built
on the n8n workflow engine, leveraging its visual workflow orchestration to automate
scheduled medication reminders, rehabilitation questionnaire delivery, message notifications,
and health news scraping. The frontend uses the WeChat Mini Program framework, providing
separate portals for patients and hospital staff. The patient portal features medication inquiry,
rehabilitation questionnaire submission, physician schedule viewing, and AI assistant
dialogue. The AI assistant is built on n8n's LangChain integration, implementing an AI Agent
with four custom Tools and the DeepSeek Chat model (temperature=0.3). The hospital portal
supports message delivery, schedule management, patient data management, and
questionnaire evaluation. Additionally, a lightweight Retrieval-Augmented Generation (RAG)
knowledge base based on the FAISS vector database and the BGE-small-zh Chinese
embedding model is integrated to provide reliable medical knowledge retrieval for the
intelligent assistant, ensuring the professionalism and accuracy of responses.
The system uses MySQL database to store business data including patient information,
medication records, messages, questionnaires, doctor schedules, and health news. Data
interaction between frontend and backend is realized through n8n Webhook interfaces. Test
results demonstrate that all functional modules operate stably, scheduled tasks execute
accurately, and the RAG knowledge base retrieval speed and accuracy meet practical

第一章 绪论
1.1 研究背景
慢性非传染性疾病（以下简称"慢病"）是全球范围内导致死亡和残疾的主要原因。
据世界卫生组织统计，心血管疾病、糖尿病、慢性呼吸系统疾病和癌症等慢病每年导致
约 4100 万人死亡，占全球总死亡人数的 71%，其中中国慢病导致的死亡人数占总死亡
人数的 88.5%，疾病负担占疾病总负担的 70%以上[1]。高血压、糖尿病、冠心病等慢病
患者出院后的持续管理，对于控制病情发展、提高生活质量具有重要意义。
慢病患者出院后的随访管理面临诸多挑战。首先，出院后患者脱离了医院的专业监
护环境，用药依从性逐渐下降，研究表明约 50%的慢病患者不能完全按照医嘱服药[2]。
其次，传统的人工电话随访方式效率低下，一名医护人员每天仅能完成数十个随访电话，
难以覆盖全部出院患者。再者，患者的康复数据难以被及时收集和分析，导致医生无法
对病情变化做出快速响应。此外，患者与医院之间的信息沟通渠道单一，信息不对称严
重影响了慢病管理的连续性和有效性。国家卫生健康委员会在《中国慢性病防治中长期
规划（2017-2025 年）》中明确提出要推进互联网与健康融合，创新慢病管理服务模式[3]。
近年来，将自动化工作流、移动互联网、人工智能等技术应用于医疗健康领域已成
为重要趋势。n8n 作为一款开源的工作流自动化平台[4]，以其灵活的流程编排能力和丰
富的集成生态，为构建智能化的医疗管理系统提供了新的技术路径。检索增强生成
（RAG）技术的成熟[5]，使得智能问答系统能够基于权威知识库回答医疗问题，有效避
免了大模型"幻觉"问题。本文基于上述技术，设计了一套覆盖出院后随访管理全流程的
智能化解决方案。
1.2 国内外研究现状
1.2.1 慢病管理信息化研究现状
在国际上，欧美发达国家在慢病管理信息化方面起步较早。美国 Kaiser Permanente
等大型医疗机构建立了集成化的患者管理平台，通过电话、邮件、移动应用等多种渠道
为患者提供健康管理服务。英国国家医疗服务体系 NHS 推出了在线问诊、电子处方、
远程监测等数字健康服务。这些系统在提高随访覆盖率和用药依从性方面取得了显著成
效，为慢病管理信息化提供了有益借鉴。

在国内，随着"互联网+医疗健康"政策的推进，各大医院陆续建设了院后随访系统，
但现有系统多基于单体架构，扩展性有限，且各系统间数据难以互通，形成了"信息孤
岛"。自动化和智能化程度不高，大量工作需要人工完成，部分系统虽实现了短信提醒
等基本功能，但缺乏基于患者个体情况的个性化随访策略和智能用药管理功能。此外，
现有系统在利用 AI 技术提供智能问答服务方面仍处于探索阶段。
近年来，随着移动互联网与可穿戴设备的普及，国外慢病管理模式正从单一的院内
管理向"医院-社区-家庭"三位一体的延续性护理模式加速转型。美国梅奥诊所（Mayo
Clinic）于 2023 年推出的远程患者监测项目（Remote Patient Monitoring）覆盖高血压、
糖尿病、冠心病等主要慢病病种，通过蓝牙血压计、血糖仪等设备实现生理数据的自动
采集与异常预警，使患者再入院率降低了约 19%[6]。英国国家医疗服务体系（NHS）在
2024 年发布的《数字化慢病管理白皮书》中明确提出，到 2028 年将实现至少 50%的
慢病复诊通过线上随访完成，以减少非必要的线下就诊压力[7]。
在用药依从性管理方面，世界卫生组织早在 2003 年就指出，发达国家慢病患者长
期用药依从率仅为 50%左右，且这一比例在发展中国家更低。近年来，基于行为经济学
理论的"轻推"（Nudge）策略被引入用药提醒领域。例如，宾夕法尼亚大学医学院开发
的 Way to Health 平台，通过短信提醒、经济激励和社交比较等多重行为干预手段，使
心梗患者的用药依从率提升了约 12 个百分点[8]。此外，澳大利亚墨尔本大学团队利用
智能手机应用结合智能药盒的联合干预方案，针对老年多重用药患者进行了为期 12 个
月的随机对照试验，结果表明干预组用药偏差率较对照组降低了 34%[9]。
值得注意的是，上述系统多为针对单一病种或单一功能（如仅用药提醒或仅随访）
的垂直解决方案，缺乏将随访计划制定、用药提醒推送、康复问卷回收、健康资讯分发
等功能整合在同一平台的统一架构，这正是本研究引入 n8n 工作流平台进行统一编排的
核心动机之一。

超过 1,000 个，覆盖从数据库 CRUD、HTTP API 调用到 LangChain AI Agent 集成的

Agent 节点结合 DeepSeek Chat 模型与自定义 Tool 集合，实现了面向慢病患者的智能
对话式随访服务。
1.2.3 智能问答与 RAG 技术研究现状
大语言模型的快速发展为智能问答带来革命性变化。Transformer 架构[13]的提出奠定
了现代大语言模型的基础。自 OpenAI 于 2022 年底发布 ChatGPT 以来，大语言模型在
医疗领域的应用呈爆发式增长。2024 年，Google Research 推出的 Med-PaLM 2 在美
国医师执照考试（USMLE）中取得了 86.5%的准确率，达到专家级水平[14]。然而，通
用大语言模型 LLM 在医疗场景中面临两大核心挑战：一是幻觉（Hallucination）问题，

2.1 n8n 工作流自动化平台
n8n 是一款开源的工作流自动化平台，采用 TypeScript 开发，基于 Node.js 运行时环
境[4]。与 Zapier、Make 等商业 SaaS 产品不同，n8n 采用了开源、可自托管的部署架构。
用户既可选择 n8n 官方提供的云服务，也可将其部署在自有服务器、私有云或本地环境
中，数据存储和传输完全由用户掌控。这一特性对于处理医疗健康、金融、政务等涉及
个人隐私和合规要求严格的敏感数据尤为重要——在医疗场景下，患者诊疗数据、健康
档案等信息必须满足 HIPAA、GDPR 等数据保护法规的合规性要求，自托管部署从根本
上规避了第三方服务商接触数据所带来的合规风险，确保数据所有权和控制权始终归属
于医疗机构本身。此外，n8n 采用公平代码（Fair-code）许可模式，社区版功能完整且
免费，相较于商业竞品的高昂订阅费用，显著降低了个人开发者和中小型团队的使用门
槛。
n8n 的核心概念围绕三个基本抽象构建：工作流（Workflow）、节点（Node）和连
接（Connection）。工作流是对一项自动化业务流程的完整定义，以有向无环图（DAG）
的形式描述了数据从触发到处理、再到输出的整个流转过程；节点是工作流中的基本执
行单元，每个节点封装了特定的功能逻辑，分为触发节点（Trigger Node）、处理节点
（Action Node）、逻辑控制节点和输出节点等类别；连接则是节点之间的有向边，既定
义了执行顺序，也承载了数据的传递路径——上游节点的输出数据会通过连接自动注入
下游节点的输入上下文，用户可通过 n8n 内置的表达式语法（Expression Syntax）或
JavaScript 函数对传递中的数据进行过滤、转换和映射。
在节点的生态丰富度方面，n8n 官方及其社区提供了超过 300 种节点类型，覆盖
了主流数据库、SaaS 服务、通信协议和开发工具。在本系统的实际构建中，主要使用了
下述节点：Schedule Trigger 用于实现周期性任务调度，支持 Cron 表达式精确定义执行
时间窗，适用于健康数据定期同步、报告自动生成等场景；Webhook 节点对外暴露标准

2.2 检索增强生成（RAG）技术
RAG（Retrieval-Augmented Generation）技术的核心思想是：不依赖大模型自身知
识回答问题，而是先从本地知识库检索与问题最相关的文档片段，将检索结果作为上下
文提供给大模型，引导其基于给定上下文生成回答。这种方式既发挥了大模型的自然语
言处理能力，又通过外部知识库保证了回答的准确性，有效降低了大模型在专业领域问
答中的"幻觉"问题。
RAG 工作流程分为索引构建和查询检索两个阶段。索引阶段将原始文档切分成合
适的文本块，使用嵌入模型（Embedding Model）将每个文本块转换为高维向量，并存
入向量数据库；查询阶段将用户的问题通过同一嵌入模型转换为向量，在向量数据库中
搜索最相似的 Top-K 个文档块，将检索结果作为上下文提供给大模型生成最终回答。本
系统嵌入模型采用 BGE-small-zh-v1.5，该模型体积仅 24MB，输出 512 维向量，在 CPU
上即可高效运行。向量数据库采用 FAISS 的 IndexFlatIP 索引[18]，对约 8500 条疾病记
录可实现毫秒级检索。Sentence-BERT 框架[19]为句子嵌入的生成提供了统一接口。

数据隔离：通过 patient_id 严格隔离不同患者的数据访问权限，患者仅能查看本人
的用药、问卷和消息记录。
敏感信息保护：微信 appid、secret 等敏感配置存储在 n8n 工作流变量中，不提交至
前端代码仓库；管理端密码以哈希形式存储。
3.3.4 可维护性需求
工作流可视化编排：所有自动化逻辑以 n8n 工作流的可视化形式呈现，节点连接关
系清晰，便于非技术人员理解业务流程。
Error Workflow 兜底：关键工作流（如用药提醒）配置了独立的 Error Workflow，当
主流程执行失败时自动触发告警通知。

耗时和错误信息，支持按时间和工作流 ID 检索。
3.3.5 可扩展性需求
工作流热插拔：n8n 支持工作流的独立启停，新增功能仅需创建新工作流并暴露

所有回复附带医疗免责声明），集成了用药查询、出诊查询、问卷查询、消息查询 4 个
工具节点，利用 Memory Buffer Window 提供基于 patient_id 的短期对话记忆。响应通过
Webhook 流式输出，前端逐段接收渲染，实现类似大模型聊天应用的逐字输出体验。

4.4 RAG 知识库设计
RAG（Retrieval-Augmented Generation）知识库为智能小助手提供权威医学知识检
索能力，是本系统确保医学回答准确性的关键技术组件。本节从知识库构建和在线检索
服务两个层面展开详细设计。
4.4.1 知识库构建模块
1. 模块功能描述
知识库构建模块负责将原始医学文本资料转化为可供语义检索的向量索引。模块输
入为 10 个 medical_coze_*.txt 文件（总计约 8468 条结构化的疾病记录，每条包含【疾
病】【描述】【症状】【病因】【预防】【治疗】【就诊科室】【常用药】等字段），
输出为 FAISS 向量索引文件（medical.index）和原始文档元数据文件（docs.pkl）。构建
过程为离线一次性执行，索引文件供在线检索服务启动时加载使用。
2. 模块流程设计
构建流程分为四个步骤。首先，遍历 10 个 txt 文件，按\n---分隔符将每个文件切分
为独立疾病条目，使用正则表达式【疾病】(.+ )提取疾病名称作为标识，每个条目以
{disease, content,source}结构存储。接着，加载 BGE-small-zh-v1.5 模型（24MB，512 维
输出），对所有条目的 content 字段进行批量编码，设置 normalize_embeddings=True 将
向量归一化到单位长度，使内积等价于余弦相似度。然后，创建 FAISS IndexFlatIP 索引
（ 内 积 索 引 ） ， 将 归 一 化 后 的 向 量 矩 阵 通 过 index.add 全 部 加 载 。 最 终 ， 调 用
faiss.write_index 将索引保存为 medical.index 文件，通过 pickle.dump 将原始条目列表保
存为 docs.pkl 文件，均存储于 faiss_index/目录下供在线服务加载。

# index_data.py 核心逻辑
# 1. 文本解析：按 "---" 分割疾病条目
def parse_disease_entries(filepath):
with open(filepath, "r", encoding="utf-8") as f:
content = f.read()
return [e.strip() for e in content.split("\n---") if e.strip()]
# 2. 提取疾病名称
def extract_disease_name(entry):
m = re.search(r"【疾病】(.+)", entry)
return m.group(1).strip() if m else "未知"
# 3. 加载模型并向量化（归一化使内积等价于余弦相似度）
model = SentenceTransformer("BAAI/bge-small-zh-v1.5")
texts = [e["content"] for e in entries]
embeddings = model.encode(texts, normalize_embeddings=True,
show_progress_bar=True)
embeddings = np.array(embeddings, dtype="float32")
# 4. 构建 FAISS 索引
dim = embeddings.shape # 512 维
index = faiss.IndexFlatIP(dim)
index.add(embeddings)
# 5. 持久化
faiss.write_index(index, "faiss_index/medical.index")
with open("faiss_index/docs.pkl", "wb") as f:
pickle.dump(entries, f)

应返回 HTTP 200 及 JSON 格式数据，业务错误通过 code 或 message 字段标识，认证失
